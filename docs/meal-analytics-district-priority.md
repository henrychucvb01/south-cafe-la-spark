# Meal Analytics district priority

School Meal Analytics now reads district and manager counts together through the verified, school-scoped `school_meal_analytics` RPC. It reuses existing manager, temporary manager, and Supervisor sessions; closes each read session; selects only the requested date range; and returns errors instead of silently substituting unofficial data when district loading fails. It changes no source records, points, staffing, imports, or reconciliation actions.

School and area Meal Analytics share a resolver keyed by operational school ID and service date. Each available district meal value, including an explicit zero, overrides the corresponding manager value. Null or missing district meals retain the manager fallback. Official-only dates are included, and official supper counts are complete even if a manager marked supper pending. Original manager rows remain unchanged for Meal Audit comparison. Existing MPLH already treats official zeros this way; the monthly scorecard's separate existing calculation is outside this change.

Read-only production verification on November 17, 2026 covered all 28 active schools for September 1–November 17. Broadacres El (operational location 12) has 163 manager lunches on September 25 and 243 official lunches. The official source records explain the total: 163 on Friday September 25 plus 80 on Saturday September 26, rolled into Friday by the existing calendar rule. Do not replace that aggregate with 163 or delete Saturday's meals. Meal Audit now explains the rollup beside the page introduction.

Validation: all-school resolution tests; partial and absent district data; genuine district zeros; manager source immutability; official-only dates; session cleanup and error handling; database authorization, school isolation, temporary manager and Supervisor reads, date bounds; existing navigation, area analytics, MPLH and full interface suite; production build. Fictional data is used for writes in isolated PGlite tests only.
