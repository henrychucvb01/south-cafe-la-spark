SPARK Rewards: Settings, Wheel Builder and Auction Preview

Development branch: rewards-management. No production deployment, main push, live data change or manager activation.

What Is Implemented

  • Compact ten-icon picker, gift default, custom icon and existing image preservation. Selected icons appear in the shared Supervisor/manager preview.
  • Fixed redemption editor: name, description, icon, point cost, Active and Fulfilled. No inventory, sold-out, schedule or per-manager limit controls.
  • Community pool editor: name, description, icon, goal, contributor-name visibility, Active and Fulfilled. No contribution limits, dates or spin unlock controls.
  • Independent Wheel Spin reward type. Each reward has its own pull, punishment or non-punishment wheel, point goal, segment configuration and session limit. All wheel setup is in the Reward Catalog. The separate legacy Challenge Wheel screen and global meeting spin-limit control are hidden; existing records and saved settings are preserved.
  • Two to twelve eligible segments; labels, colors, outcomes, values, approval, enable/disable, add/delete, equal-chance test spins, live draft preview, visible pointer, adaptive label contrast, reduced-motion and fullscreen support. Changing a wheel type asks before replacing its draft segments.
  • Silent Auction configuration: starting bid, private reserve, minimum increment, auction dates and independent anti-sniping trigger/extension settings. Defaults: enabled, two-minute trigger and two-minute extension.
  • Read-only manager previews show claimed/fulfilled states, pool progress and optional contributor names, wheel unlock status and test preview, highest/starting bid, minimum next bid, reserve-met status, countdown, leading/outbid status and extensions. Bidder names, schools and reserve amounts are not rendered on auction cards.

Test Workflows

In Supervisor Rewards Management, choose Test Workflows. It is an explicitly labeled, in-memory rehearsal with two synthetic schools and SPARK Point balances. It cannot call a points or spending endpoint. Closing the dialog discards the rehearsal. Existing catalog entries are copied, not edited, and four ready-to-test examples are included.

The rehearsal covers confirmation, single-school claims, positive whole-point contributions capped at the goal and available balance, goal notifications, optional contributor visibility, reservation-aware bids, own-bid increases, outbids and released reservations, reserve-aware settlement, repeated anti-sniping extensions, one goal/one wheel session, capped extra spins, follow-up outcomes, session closure, fulfillment, cancellation/refunds and request retry protection. A practice clock can advance one minute at a time. Practice school balances are not additional live currency or accounts.

Not Yet Implemented for Real Managers

The live financial and session workflows are incomplete and remain blocked server-side. Rehearsal correctness is not a substitute for server authorization, database transactions or concurrency testing. No real reward has been redeemed, funded, bid on, refunded, spun or fulfilled through these workflows.

Accounting Integration Findings

Schools use the existing season balance function over public.spark_points. Bingo and Mystery Photo purchases coordinate using the october_live.settings row lock. Live auction holds must participate in that same spending boundary so those games cannot consume reserved points. This update deliberately does not modify those unrelated game functions or introduce a second live balance or ledger.

Database Scope

The guarded local upgrade in scripts/rewards-builder-schema.sql extends the private development catalog to accept Wheel Spin configuration and validates all new settings. It does not delete or rewrite reward, transaction, audit or school records. It does not change manager activation or authorization. It runs only through the isolated local fixture; nothing was applied to a Supabase host.

The Supabase CLI could not run on this host because its Windows binary package was unavailable. This file is an isolated-development schema upgrade, not a generated production migration. A reviewed migration and advisor/concurrency checks remain required before any future deployment.

Verification Scope

Tests cover the editors, icons, preview privacy, safe test spins, the in-memory workflow rules, additive schema preservation, authorization and continued manager-spending denial. These do not certify real financial operations. Detailed test results are reported with the handoff.

Verified: 483 regression tests across 93 suites; both isolated database test scripts; development/production API isolation checks; optimized production build; desktop/mobile browser navigation, wheel builder, test spins and workflow rehearsals. Browser writes are intercepted in memory, preserving the user's local catalog as well as production data. The existing bundle-size advisory remains.
