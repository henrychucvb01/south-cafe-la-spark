Development only. Manager launch is locked. Nothing was deployed or pushed to main.

Open the local SPARK preview, choose Supervisor Access, and use the synthetic PIN 2468. Select Rewards Management in the Supervisor sidebar. Choose a synthetic school and select Preview Manager Rewards Page.

This is a separate copy of main at commit 71e3b3c, on local branch rewards-management. All local accounts, balances and records are synthetic. Settings persist in the ignored local .rewards-runtime/database directory. The original main checkouts and all production data are untouched.

Functional Foundation

  • Eleven initial catalog entries, all Draft, inactive and unpriced. None are automatically published.
  • Create, edit, duplicate-as-draft, filter, activate/deactivate, draft/published configuration, dates, point settings, quantities, an Active checkbox and a Fulfilled checkbox.
  • Server validation, stale-edit protection and an audit trail for configuration changes.
  • The actual shared manager card layout, category filters, accessible help disclosures, school season balance, draft labels, and desktop/mobile Supervisor preview.
  • Wheel challenge creation, editing, approval, activation and retirement. Equal chance for each active approved segment; animated preview, reduced-motion support, fullscreen presentation and internal preview result snapshots.
  • Preview request IDs prevent duplicate result records after retries. Retiring or renaming a wheel challenge preserves its previous result labels.

Simplified Supervisor Controls

The catalog has no prize icon, separate status selector, maximum claims per manager, refund policy or approval-required field. Fulfillment is a single checkbox. Checking Approved immediately adds a challenge to the wheel preview; Remove excludes it. One Save Wheel button persists all pending edits. Configuration and spin history are not displayed; internal safety records remain intact. School prize-spending history belongs to Phase 2, when spending is enabled.

Activation and Manager Access

The global activation setting defaults to false and is stored in the development database. Phase 1 deliberately locks the checkbox off: publishing a reward does not launch Rewards. A server-side readiness lock must be replaced only after Phase 2 financial workflow validation and explicit Supervisor approval.

Managers see no Rewards banner while inactive. Direct API access and all participation actions are rejected server-side. The existing Games banner and Spotlight placement remain intact. The future navy/gold Rewards banner and shared manager page are wired behind the launch gate, not displayed as disabled manager controls.

Phase 2: Not Implemented or Activated

Community contributions and goal completion, fixed claims and approval deductions, auction reservations/settlement/ties, bid privacy/history, refunds/cancellation accounting, earned spin entitlements, real spin use and manager activity records remain Phase 2. No transaction or reservation ledger was created. No manager spending endpoint is enabled. Preview spins are explicitly marked as tests and cannot become redeemed spins.

The existing SPARK balance is school-owned. Preview reads the existing season balance function; no additional points, currency or account balance is introduced. Phase 2 must integrate atomic reservations and deductions with every existing spender before enabling manager participation.

Database Scope

The development migration creates only rewards_dev configuration, preview spin and audit tables plus one Supervisor-authorized RPC. Tables have RLS enabled and no direct anonymous/authenticated access. It requires explicit spark.rewards_development=on in an isolated development database. It was executed only in local test databases, not in a live Supabase project.

The API requires the development opt-in and refuses production execution. Existing database isolation rejects the SPARK production URL in development. No existing authentication, school, SPARK Points, game or reward table is changed by this migration.
